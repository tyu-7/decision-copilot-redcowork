# Decision Copilot

这个目录是独立的纯前端提交项目。需要建立 GitHub 仓库时，以本目录为仓库根目录，不要上传上层的 P0 历史工程。

## 运行与构建

- 双击 `index.html` 可审阅页面。
- 使用 Node.js 18 或更新版本，执行 `npm run build`，静态产物在 `dist/`。
- 构建没有外部依赖，不需要安装框架或连接后端。
- `npm test` 检查流程、草稿恢复、确认边界和更新行为；这不等于浏览器视觉测试。
- 静态托管时入口为 `dist/index.html`。导入平台的具体操作需要按平台实际界面确认。

## 可以体验什么

首页有「开始我的决策」和「体验智能梳理」两个入口。

示例流程：直接展示 AI 预置追问（原始描述可展开）→ 选择或改写回答 → 查看三处草稿变化 → 核对材料 → 同维度 A/B 对比 → 保存自己的行动 → 补充后续答复 → 核对并保存本次变化。

个人流程：填写两条路径 → 手动添加依据、底线或待验证问题 → 查看对比 → 保存行动 → 后续更新。

所有实习岗位和答复都是虚构材料。示例采用预置 AI 对话与本地规则，不调用实时模型。自定义条件没有对应材料时保持未知。用户保存的内容仅保存在当前浏览器，使用不同来源或浏览器时不会同步；存储不可用时会显示提示。同一浏览器分别保存一条个人决策和一条示例记录。体验或重置示例不影响个人记录；新建个人决策前会说明替换行为。

## 第四轮交互改进

- 关联材料修改、撤回或替代后，只把相关判断标为待复核。历史值不当作当前结论，重新选择状态并确认后才生效。
- 未分类信息可由用户选择对应信息和共同维度配对；已完成决策先预览变化再保存。
- 底线、关键问题及本次更新涉及的维度优先显示。
- 确认弹窗选择后恢复当前按钮焦点与滚动位置。
- 更新预览列出具体前后内容；改名称与更换方案分开核对。更换方案后原材料保留为历史，确认适用后才重新参与该侧对比。
- 手机文字入口增加点击留白与最小 44 像素高度。
- 相关信息更新后突出行动复核，支持已完成、仍需继续与记录新行动，保留历史。
- 上轮漏点确认、示例隔离、手动录入、展开恢复、替代撤回与日期提示保留。
- `npm test` 包含 61 项状态、页面内容和模拟页面对象检查；实际浏览器视觉检查仍待完成。

## 第五轮边界修复

- 连续更换方案逐次隔离材料，中间方案信息不自动适用于最终方案；原材料留作历史，适用性由用户重新确认。
- 暂不纳入的条件退出当前速览和对比；改写底线后当前判断重置为未知，原判断在条件编辑区明确对应原条件。
- 手机长按钮独占一行并允许换行，避免与相邻按钮重叠。
- 行动历史保留已完成／被新行动替代及已有时间，已完成行动停止显示待执行日期提醒。
- 旧版未保存的方案变更需再核对一次，正文保留，不要求清空整条记录。

## 第六轮衔接修复

- 路径修改后先确认改名／换方案，再为当前方案录入；已有草稿保留，确认后再次点击加入。没有最终确认前，材料入口保持暂停，退出／刷新也不会提前更换方案身份。
- 修改底线／问题的关联材料，按钮立即显示重新确认并说明原因；确认反馈与继续时的校验一致。
- Escape 与「稍后再分」使用相同取消流程；清除空临时更新并恢复配对入口，已有更新和输入保留。
